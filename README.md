> 專案狀態與工作進度文件。後續新增科目、學期、章節、題庫、錯題診斷或資料結構時，請同步更新本 README。
>
> 最後更新：2026-09-12

## 1. 專案目標

這個專案要逐步建立一套可在手機與電腦使用的「國中線上題庫」。

主要方向：

- 依「科目 → 年級／學期 → 章節 → 難度」進入題庫。
- 每個章節可建立簡易、中等、困難等不同層級題目。
- 作答後立即評分、顯示正確答案與詳解。
- 保存成績與錯題，供後續複習。
- 錯題可交由 AI 依「該章課文知識基準」分析真正的弱點，而不是只做一般性評論。
- 題庫內容與學習紀錄分離：公開網站不存放私人學習資料或 API Secret。

## 4. 已完成：自然一上「科學方法」題庫

目前第一個可完整作答的章節為：

```text
自然
└─ 七年級上學期（一上）
   └─ 第 1 章 科學方法
```

每個難度 20 題，每題 5 分，滿分 100 分。

### 簡易

以基本觀念為主：

- 科學方法基本步驟
- 觀察、問題、假說、結論
- 操縱變因、應變變因、控制變因
- 簡單的實驗組／對照組概念

### 中等

以情境應用為主：

- 實驗組與對照組
- 變因判讀
- 實驗結果判讀
- 科學方法在情境題中的應用

### 困難

以分析能力為主：

- 資料判讀
- 實驗設計缺陷
- 控制變因
- 結論是否被資料支持
- 實驗結果與假說的關係

## 5. 題庫目前已有的功能

### 作答

- 每章可選「簡易／中等／困難」。
- 目前各 20 題。
- 作答進度即時顯示。
- 可以有未作答題目再交卷。
- 答案選項每次進入考試會重新隨機排列。
- 隨機排列後會同步重算正確答案位置，不影響評分。

### 評分與詳解

- 交卷後計算分數。
- 正確答案以綠色顯示。
- 本次選錯答案以紅色顯示。
- 可切換顯示／隱藏詳解。
- 可以重新作答。

### 成績紀錄

- 本機保存每次作答成績。
- 紀錄難度、分數、答錯數、未答數、作答時間等。
- 未作答與答錯分開計算。

### 錯題複習

- 只記錄「有作答但答錯」的題目。
- 未作答不列入錯題。
- 顯示學生寫錯的答案與正確答案。
- 累積同一題的錯誤次數。
- 可清除本機錯題紀錄；清除錯題不等於刪除完整成績紀錄。

## 6. AI 錯題診斷

目前錯題分析使用 Google Gemini。

目前後端模型：

```text
gemini-3.5-flash-lite
```

AI 不只接收「題目／學生錯答／正確答案」，還會讀取該章節的課程知識基準，再做判定。

目前科學方法章的知識基準：

```text
Exam-Record/curriculum/science-method.json
```

內容包含：

- 本章核心流程
- 課本概念與定義
- 三種變因
- 實驗組／對照組
- 實驗紀錄與資料分析
- 假說與結論
- 常見迷思
- 診斷分類
- AI 診斷限制

### AI 診斷原則

AI 必須：

- 先看章節知識基準，再看學生錯題。
- 只指出錯題真正支持的弱點。
- 不可因一題錯就說整章不熟。
- 不可自行擴充成高中、大學程度內容。
- 錯題少時不得硬湊三個弱點。
- 用國一學生看得懂的繁體中文。
- 避免研究報告式或過度學術的語言。
- 優先說清楚「這次混淆了什麼、兩者差在哪、下次如何判斷」。
- 複習建議應是 5～10 分鐘可執行的小動作。

目前輸出格式大致為：

```text
重點診斷
...

最需要加強
① ...
② ...（有證據才出現）

今天怎麼複習
① ...
② ...
③ ...
```

## 9. 安全規則

### GitHub Token

網站用來同步私人 `Exam-Record` 的 GitHub fine-grained PAT：

- 不可寫入 repository 原始碼。
- 不可寫入 README。
- 不可貼到 ChatGPT 對話。
- 前端目前只存於 `sessionStorage`。

### Gemini API Key

Gemini API key：

- 不可放進公開 GitHub Pages JavaScript。
- 存在私人 `Exam-Record` 的 GitHub Actions Secret。
- Secret 名稱：`GEMINI_API_KEY`。

README 不應紀錄任何 token、password 或 API key 實值。

## 10. 建置原則

### A. 先確認教材，再建立章節

新增章節時應先取得實際課本／講義內容，再確認：

- 科目
- 年級
- 上／下學期
- 章節名稱
- 範圍
- 核心概念

不要先憑印象建立完整章節表。

### B. 題目不是只求數量

每一章題庫應盡量覆蓋：

```text
基本記憶
→ 概念理解
→ 情境應用
→ 資料判讀
→ 高階錯誤辨識／實驗設計
```

### C. AI 診斷不能只靠模型常識

每一章正式加入 AI 錯題診斷前，最好建立自己的 curriculum knowledge base，例如：

```text
curriculum/<chapter-id>.json
```

AI 應以該檔案為本章判定基準。

### D. 未答不等於答錯

整個系統維持：

```text
答對
答錯
未答
```

三種狀態分開處理。

未答不得進錯題清單，也不得被 AI 當成錯誤觀念證據。

### E. 選項可以隨機，但概念不能跟著漂移

選項每次可以重新排列；正確答案必須跟著重新定位。

錯題分析應優先使用「答案文字／概念」，不要把 A、B、C、D 當成長期識別依據。
